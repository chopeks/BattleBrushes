# Battle Brothers Brush Plugin - Complete Technical Documentation

## Project Overview

This project implements native Battle Brothers .brush file support in Tiled as a C++/Qt5 plugin, enabling UI-only workflow for artists without external tools like bbrusher.exe.

### Data Structures

**BrushHeader** (`brushplugin.h:57-65`)
```cpp
struct BrushHeader {
    QString sheetPath;               // Atlas image path
    quint16 version = 17;           // Format version
    QString category;               // terrain, detail, object, entity
    quint8 b1, b6, b9, b11;        // Unknown header fields
    quint32 i0;                    // Unknown header field
    quint16 spriteCount;           // Number of sprites
    quint16 atlasWidth, atlasHeight; // Atlas dimensions
};
```

**SpriteRecord** (`brushplugin.h:38-55`)
```cpp
struct SpriteRecord {
    QString id;                     // Sprite identifier
    QByteArray blob;               // 8-byte opaque data
    QRect rect;                    // Position in atlas (computed)
    QPoint offset, edges;          // Unused positioning data
    quint16 flags;                 // Unused flags
    quint32 averageColor;          // ARGB color if available
    QString srcPath;               // Relative file path
    quint32 width, height;         // Sprite dimensions
    float leftNorm, rightNorm;     // UV coordinates (0-1)
    float topNorm, bottomNorm;     // UV coordinates (0-1)
    QByteArray postPathHex;        // Debug data
};
```

## Binary Format Understanding

### File Structure
```
0x00-0x03: Magic bytes (0xBAADFAAD little-endian)
0x04-0x05: Version (17)
0x06-0x07: Sheet path length
0x08-0x??: Sheet path string (null-terminated)
0x??-0x??: Category string (null-terminated)
0x??-0x??: Header fields (b1, b6, b9, b11, i0)
0x??-0x??: Sprite count (16-bit)
0x??-END:  Sprite entries (paired records)
```

### Sprite Entry Format (Paired Entries)
Each sprite has exactly 2 entries:

**Entry 1: Metadata Record (48 bytes)**
- Sprite ID, dimensions, 8-byte blob, positioning data

**Entry 2: Path Record (variable length)**  
- File path string + UV coordinates (16 bytes: u0,v0,u1,v1 as floats)
- **Critical Discovery**: UV coordinates located immediately after ".png\0" terminator

### Coordinate System Issue
**Problem**: Battle Brothers uses bottom-left origin, images use top-left
**Solution**: Y-coordinate flip during sprite extraction

2. **Coordinate positioning** - Some sprites cropped from wrong atlas locations
3. **Build system fragility** - Parsing code corrupted during investigation

### 🎯 Required Fix
Single coordinate transformation in `loadAtlasAndCropSprites()`:
```cpp
// Current:
QRect cropRect = spriteRecord.rect;

// Fixed:
QRect cropRect = spriteRecord.rect;
int atlasHeight = atlas.height();
int flippedTop = atlasHeight - cropRect.bottom();
int flippedBottom = atlasHeight - cropRect.top(); 
cropRect = QRect(cropRect.left(), flippedTop, cropRect.width(), flippedBottom - flippedTop);
```
